# Сборка с возможностью прерывания

Скрипты HumanGram спроектированы так, чтобы сборку можно было в любой
момент прервать — в том числе выключить компьютер — и продолжить с того
же места, без потери уже сделанной работы.

## Единая точка входа

```powershell
pwsh -File build\resume.ps1              # продолжить всё
pwsh -File build\resume.ps1 -Status      # только отчёт о состоянии
pwsh -File build\resume.ps1 -Only Android -Universal
```

`resume.ps1` можно запускать сколько угодно раз: он сначала приводит
рабочее дерево в согласованное состояние, затем определяет, что уже
готово, и выполняет только незавершённое.

## Что происходит после прерывания

| Слой | Поведение при перезапуске |
|---|---|
| HumanGram-Proxy (Go) | Кэш компиляции на диске G. Пересобираются только изменившиеся пакеты. |
| Gradle | Кэш и состояние задач в `G:\HumanGram\.cache\gradle`. Выполненные задачи помечаются `UP-TO-DATE` и не повторяются. |
| CMake / NDK | Инкрементальная сборка в `TMessagesProj\build\intermediates\cxx`. Продолжается с последнего объектного файла. |
| Подготовка зависимостей | `prepare.py` хранит ключи готовых стадий: они помечаются `SKIPPING` и не пересобираются. |
| Исходный код | Копии клиентов — обычные клоны git; правки выгружены отдельно в `docs/patches/`. |

Перед сборкой `resume.ps1` выполняет восстановление:

* завершает зависшие процессы (`java`, `ninja`, `cmake`, `msbuild`,
  `python` из `prepare.py` и другие);
* удаляет устаревшие файлы блокировок Gradle — именно они чаще всего
  мешают продолжить прерванную сборку;
* снимает блокировку индекса git, если она осталась после выключения.

## Проверка целостности

Скрипт не доверяет состоянию вслепую. Готовый APK проверяется на
согласованность архитектур: Android определяет поддерживаемые ABI по
содержимою каталога `lib/`, поэтому APK, объявивший четыре архитектуры
без основной нативной библиотеки `libtmessages.49.so` в них, упал бы
при запуске на устройстве с другой архитектурой. Такой APK помечается
как требующий пересборки.

## Честное ограничение

Это не транзакционная файловая система. Если выключение произойдёт
ровно в момент записи файла, повреждённым может оказаться один файл.
Восстановление рассчитано на повреждение состояния, а не данных: все
промежуточные результаты выводятся заново из исходников, а готовые
артефакты проверяются перед использованием.

Поэтому рабочий процесс такой:

1. Исходники HumanGram лежат в git и уже отправлены в репозиторий.
   Потерять их невозможно: состояние восстанавливается клонированием.
2. Тяжёлые клоны клиентов (`desktop/`, `android/`) и подготовленные
   зависимости исключены из репозитория как воспроизводимые, но
   требуют много времени на повторную загрузку.
3. Ключ подписи Android исключён из репозитория намеренно. При его
   утрате сборка получит новую подпись и не сможет обновлять ранее
   установленное приложение. Скопируйте
   `android\TMessagesProj\config\release.keystore` в надёжное место.

## Диск C

Все промежуточные данные размещены на диске G: кэш Go
(`G:\HumanGram\.cache\go-build`), кэш Gradle
(`G:\HumanGram\.cache\gradle`), Android SDK (`G:\HumanGram\android-sdk`),
зависимости клиентов (`G:\HumanGram\ThirdParty`, `G:\HumanGram\Libraries`).
